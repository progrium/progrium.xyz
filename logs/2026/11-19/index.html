📝 The dotfs protocol for 9P ↗ progrium.xyz

A draft proposal for dotfs, four small, independent extensions a 9P server can expose as synthetic files under .fs/: an index of the whole tree's metadata in one read, a stream of change events, path operations like mv and rm without walk, open, and clunk sequences, and staged commits that publish atomically only if a path is still at an expected version. A server implements just the ones it needs, and clients discover each by whether its file exists. Together they're enough to build a Dropbox-style synced folder, but nothing in the first three depends on sync.
